# Pricing page e2e spec realignment

## Environment and scope

- Date: 2026-10-18
- Environment: local Angular workspace, Playwright (chromium), all API calls mocked
- Branch: `development`
- Scope: `e2e/plan.spec.ts` only. No app code changed.

## Problem

4 of 12 tests in `e2e/plan.spec.ts` failed. The spec still described an older pricing page:

- Billing toggle looked for `input[type="checkbox"]`; the page now uses a `p-selectButton`
  group labelled "Billing period" with Monthly / Yearly buttons (`aria-pressed`).
- Custom plan CTA looked for "Contact sales about the Enterprise plan"; the label is now
  "Talk to sales about the Enterprise plan" (`pricing-card.ts`).
- Custom plan selection expected a redirect to `/auth/register-institution?planId=3`; the page
  now opens a sales `mailto:` instead (`pricing.ts` `onPlanSelect`), already covered by
  `pricing.spec.ts` ("never sends a custom plan down the self-serve route").

## Decision

- Billing tests target the "Billing period" group's buttons and assert `aria-pressed="true"`.
- CTA tests use the "Talk to sales" accessible name.
- The custom-plan selection test now asserts the URL stays on `/auth/plan`. Chromium does not
  allow stubbing `location.assign`, so the mailto href stays covered by the unit spec only.

## Locked-fix gate

The registry named in `AGENTS.md` (`Skolenza.be/main_branch/LOCKED_FIXES.md`) returned 404 from
both raw GitHub and `gh api`. The user approved proceeding without it for this spec-only change.
