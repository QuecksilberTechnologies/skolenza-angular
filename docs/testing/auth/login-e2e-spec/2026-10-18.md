# Login page e2e spec realignment

## Environment and scope

- Date: 2026-10-18
- Environment: local Angular workspace, Playwright (chromium), all API calls mocked
- Branch: `development`
- Scope: `e2e/login.spec.ts` only. No app code changed.

## Problem

The spec described an older login page and left newer behaviour uncovered:

- Invalid-email assertion used the short message; the schema now reads
  "Please enter a valid email address. (e.g. user@example.com)." (`login.schema.ts`).
- No coverage for the disabled "Remember me (coming soon)" checkbox, the disabled
  Google / Microsoft / Apple sign-on group, Enter-key submit, the manager (roleTypeId 3)
  redirect, or the "no role assigned" error (`login.ts` `#handleLoginResponse`).
- Create-account navigation used `#btnCreateAccount` instead of the link's accessible name.

## Decision

- Assert the full invalid-email message and the subheading.
- Add tests for: remember me and SSO disabled with the "coming soon" hint, Enter submits,
  roleTypeId 3 lands on `/app/admin-dashboard`, a login with `primaryRole: null` (non-host)
  shows the no-role error and stays on `/auth/login`.
- Create-account test targets the "Create an account" link by role.
- Reworded "an staffMember" test titles to "a staff member".
