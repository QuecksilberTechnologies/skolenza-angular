# Host Staff Category Catalogue UI review fixes

## Environment and scope

- Date: 2026-10-15
- Environment: local Angular workspace
- Branch: `development`
- Scope: `features/host/institution-master-data/staff-category-catalogue`
  layout, breadcrumb, validation feedback, and deactivate confirmation

## Changes

- Breadcrumb set on init (`Institution Master Data > <page title>`); it previously
  kept the previous page's items (for example `Card Inventory > Add Card`).
- Borders use `border-gray-200` / `dark:border-zinc-700`. A bare Tailwind v4
  `border` renders in `currentColor`, which drew black lines.
- Duplicate in-card title and description removed; an `sr-only` `h1` keeps the
  heading outline.
- List and form panels align to the top (`items-start`) instead of stretching.
- System/Custom and Active/Inactive badges use `p-tag` severities.
- The row being edited is highlighted (`aria-current`); Edit focuses the Code
  field so the form scrolls into view below `xl`.
- Save is no longer disabled while the form is invalid, so submitting a blank
  form shows the required-field errors. A Clear button resets the Add form.
- Deactivate opens a confirmation dialog (Deactivate / Keep Active). Activate
  stays one click.

## Follow-up: form moved to a dynamic dialog

- The side-panel form moved into `staff-category-form/` (`StaffCategoryForm`), opened
  through `DialogService` the same way the billing catalogs open theirs. The schema moved
  with it (`staff-category-form.schema.ts`).
- The page is now a single-column list with an "Add Staff Category" button. Edit opens
  the same dialog prefilled. The dialog closes with `true` after a save, which reloads
  the list. Cancel or X closes it without reloading.
- The row highlight, the Clear button, and the Edit focus handling were removed. The
  modal dialog replaces them, and Code gets autofocus when the dialog opens.
- Command: `bun run test -- --include "src/app/features/host/institution-master-data/**/*.spec.ts"`
- Result: 10 passed, 0 failed (catalogue 6, form 4). ESLint and `oxfmt --check` clean.
- Not verified in a browser.

## Follow-up: loading layout shift

- Measured in Chrome (rem = 13px): a shimmer row was 79px and a real row 89.56px, so
  the list jumped about 53px when data arrived. A reload after every save also swapped
  the rows for shimmer and back, which shifted the layout twice.
- The shimmer row now mirrors the real row line for line: a 1.8125rem title line (the
  p-tag height), two `text-sm` `h-[1lh]` lines with `mt-1`, the same flex-col/sm:flex-row
  layout, and a 2.2163rem action strip (the small p-button height) that is also shown
  on mobile.
- Shimmer shows only on the first load (`loading() && !categories().length`). A reload
  keeps the current rows.
- Chrome measurement after the fix: shimmer row 89.5625px equals real row 89.5625px;
  info block 62.5625px both; actions 28.80px vs 28.81px.
- Window resize was not applied by the browser tool, so the mobile width was not
  rendered. The stacked height is the sum of the same matched parts.
