# Staff Curriculum & Lesson Delivery UI review fixes (1-5)

## Environment and scope

- Date: 2026-10-16
- Environment: local Angular workspace
- Branch: `development`
- Scope: `features/staff-members/staff-curriculum-delivery` (`.html`, `.ts`, `.spec.ts`)

## Changes

1. Dark mode: all 10 list and form panels hard-coded `bg-white` and bare `border`, so in
   `.dark` names, form headings and field labels could not be seen. The panels now use
   `border-gray-200 bg-white dark:border-zinc-700 dark:bg-zinc-900`, the same as the Professional
   and Academic Structure screens. Row borders (`last:border-b-0`), topic cards, the nav border,
   muted text and the syllabus progress track (`dark:bg-zinc-800`) get dark variants as well.
2. Delete confirmation: `p-confirmDialog` renders `message` through `[innerHTML]`, so the
   record label now goes through `escapeHtml` (`shared/utilities/escape-html.ts`). The dialog
   icon used Tailwind v3 important syntax (`!text-red-400 !text-xl`), which v4 ignores. It is
   now `text-red-400! text-xl!`.
3. Breadcrumb: the header showed the description and gave no way back. `ngOnInit` now sets
   `isBreadcrumbShow: true` and the items "Staff Directory" (`/app/staff`) >
   "Curriculum & Lesson Delivery".
4. Default delivered date: `usePlanForDelivery` used `new Date().toISOString().slice(0, 10)`,
   which is the UTC day, so it gave yesterday's date between 00:00 and 05:30 IST. It now uses
   `localDateKey()`.
5. Approved records: Edit is hidden on APPROVED frameworks and lesson plans, so approved
   content cannot be changed without going back through review. This is a UI-only guard. The
   user did not confirm whether the backend resets status to DRAFT when an approved record is
   saved, so the backend does not enforce it.

## Not changed

- Delete wording stays "Delete". The user did not confirm whether these endpoints hard-delete
  or soft-deactivate, and the dialog text ("Records already in use must be removed first")
  suggests a hard delete.
