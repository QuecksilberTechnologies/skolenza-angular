# Staff structure form control names, policy mapping route and self-edit name sync

- Branch: `development`
- Scope: `staff-academic-structure`, `staff-curriculum-delivery`, `staff-operations` and
  `staff-professional-structure` templates; `features/policies` leave staff member
  policy mapping; `staff-member-manage-dialog`
- Trigger: `/code-review` findings on the uncommitted working tree

## Decisions

- **Naming `p-select` controls.** Optimus `Select` renders `inputId` on a
  `<span role="combobox">`. A `<label for>` cannot name a span. When the select has a
  value, the span's `aria-label` is that value's option text. A select therefore gets
  its accessible name from `aria-labelledby`, which takes precedence over
  `aria-label`. The wrapping label carries `id="<inputId>-label"` and the select carries
  `ariaLabelledBy="<inputId>-label"`. The `for` + `inputId` pair stays only so
  ESLint `label-has-associated-control` passes.
- **Selects with no visible label** (substitute-row workflow and substitute, workflow
  step approver type and approver, status filter) use `ariaLabel`. Repeated step rows
  include the step number (for example "Step 2 approver").
- **`p-checkbox` labels keep `for` + `inputId`.** `eslint.config.js` sets no
  `controlComponents`, so the lint rule does not recognise `p-checkbox` as a control.
  Without `for`, those labels fail lint.
- **`select-field` was not used.** Every select in these 4 templates binds `ngModel`,
  and `shared/components/select-field` only binds `formControlName`.
- **Self-edit name sync.** Commit 378e184 replaced the profile edit dialog with the
  `/app/staff/:staffMemberId/edit` route and dropped the call that refreshed the
  header name. `StaffMemberManageDialog` now fetches the profile summary after a
  successful update when the edited staff member is the signed-in user. It then calls
  `AuthStore.updateStaffMemberName`. The request has no `takeUntilDestroyed`, because
  `finish()` navigates away straight after it.
- **Leave staff member policy mapping.** The route path is now
  `leave-staff-member-policy-mapping`, which matches the Policy Types menu link and
  the breadcrumb. The route `title` gains the app suffix. User-facing copy says
  "Staff Member". The scaffold text "works!" is replaced with "This page is not
  available yet."

## Code review follow-up — 2026-10-16

- Select labels: the `aria-labelledby` target used to be the wrapping `<label>`, so each
  combobox name also included its own selected value. The label text is now in a
  `<span id="…-label">` and `ariaLabelledBy` points at that span. The three
  `p-multiselect` controls use the same pattern. `for` stays on each label, because
  `label-has-associated-control` requires it. Moving these into `select-field` is
  deferred.
- Route: `leave-staffMember-policy-mapping` now redirects to
  `leave-staff-member-policy-mapping`, and `docs/specs/policy-flow.html` uses the new
  path.
- Self-edit name sync: the GUID comparison is case-insensitive, the profile-summary
  request has an error handler, and a failed storage write is caught. The save has
  already succeeded, so a failure only leaves the old name in the header.
- Kept `fetchProfileSummary` rather than building the name locally. The header uses the
  server-formatted `fullName`, and the refresh also updates the profile summary signal,
  which the removed `#refreshProfileSummaryAndMenu` did as well.
- Locked-fixes gate: the registry is still unreachable (404). The user approved going
  ahead without it.
- `bun run test` on the staff-members, policies, shared staff-member and layout specs:
  38 files, 183 passed, 0 failed. `bun run lint` (run by the user): all files pass.
