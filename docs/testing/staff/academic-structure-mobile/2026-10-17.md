# Academic structure: mobile layout fixes

## Environment and scope

- Date: 2026-10-17
- Environment: local Angular workspace
- Branch: `development`
- Scope: `shared/components/route-tabs`, `features/staff-members/staff-{academic,professional}-structure`,
  `staff-curriculum-delivery`, `layout/app-aside-menu`, `layout/layout.html`, `styles.css`,
  attendance and payroll status filters, and every `calc(100vh…)` / page `h-screen` in `src/app`

## Problem

A review at about 560px wide found:

- The route tabs shared a row with the toolbar (status filter, Add button). The tab list is
  `min-w-0 flex-1`, so `flex-wrap` never moved the toolbar down and the strip shrank to about two
  visible tabs. The open tab (Sections) was scrolled out of view.
- Descriptions were truncated, and the full text only appeared in a hover tooltip, which touch
  users can't open.
- Records came back in plain text order, so "Grade 10" came before "Grade 1".
- The status filter just read "All", with no visible hint that it filters by status.
- The shell and page heights used `100vh`, which on mobile browsers includes the space under
  the browser's address bar, so the bottom of each page could be hidden behind it.

## Decision

- `RouteTabs`: below `lg` the tab list takes the full width and the toolbar wraps onto its own
  row underneath. The tab list keeps its own bottom border there; from `lg` the shared border
  on the wrapper takes over again, as before. When the projected toolbar holds only
  `display: contents` wrappers (nothing to show), the toolbar row is hidden, so it leaves no gap.
  This affects every page using `app-route-tabs`.
- `RouteTabs` scrolling: an `afterRenderEffect` scrolls the selected tab into view on first load,
  on route changes, when the tab list changes and when the strip is resized (a `ResizeObserver`
  feeds a width signal, so rotating a phone can't leave the tab clipped). It adjusts `scrollLeft` on the strip
  (`.p-tablist-content`) only. `scrollIntoView` was rejected because it also scrolls the page
  and the shell's `overflow-hidden` containers. Clicked tabs are already handled by `p-tabs`
  itself.
- Structure pages (academic, professional, curriculum delivery) on mobile:
  - Below `sm` row descriptions wrap instead of truncating. From `sm` they truncate as before.
  - Rows and the card use tighter padding on mobile (`p-3`, `m-2 p-2!`).
  - The toolbar select stretches to fill its row below `lg`.
- Status filter copy: the "All" option in status selects reads "All statuses", the label most
  pages already used. Changed here: academic structure, professional structure, attendance and
  payroll overview. The notifications "All" tab stays, because it's a tab, not a status filter.
- Toolbar convention: projected toolbar content goes inside `<div toolbar class="contents">`,
  now documented on `RouteTabs`. The empty-row rule relies on that wrapper.
- Viewport units:
  - `layout.html` (`main` and the aside menu) uses `h-dvh` instead of `h-screen`, and the aside
    menu's `max-height` uses `100dvh - 55px`.
  - The page scroll-box height is one utility in `styles.css`: `h-page` / `min-h-page` =
    `calc(100dvh - 4.6rem)`. It replaces the 90 copies of `h-[calc(100vh-4.6rem)]`, so a change to
    the header height is now a one-line edit.
  - Every other `calc(100vh…)` in `src/app` is now `calc(100dvh…)`: dialog `max-h`, the policy
    version workspace, profile cards, the project views and the asset/department side panels.
  - The `h-screen` drawer placeholders (department and staff filters, asset detail, plan
    details) use `h-dvh`.
  - Desktop is unchanged, because `dvh` equals `vh` there. Plain `vh` caps on dialogs
    (`90vh`, `80vh`, `70vh`) were left as they are.

### Rejected

- A natural sort by name on academic records was tried and reverted. It mixed sections from
  different groups together (A, A, B, B) and put sessions oldest first. Records keep the API order.

### Follow-up (not done)

- A full shell refactor, where the content column is a flex column that pages fill with `h-full`
  (as several forms already do), was deferred. It changes how about 90 routed pages and 6 nested
  shells (learning, PMS, payroll, project views, settings, staff profile) get their height. The
  pages share no structure, so it needs a page-by-page browser pass to catch layout breaks.
  `h-page` keeps the header offset in one place in the meantime.

### Not changed

- Add button contrast: the preset keeps Aura's dark-mode `-400` primary fill with dark text,
  which already passes AA (see `core/skolenza-preset.ts`).
- The "Active" badge on every row, the descriptions that repeat the row name (seed data), and
  the header icon tap targets (they pass AA's 24px minimum) were left as they are.
