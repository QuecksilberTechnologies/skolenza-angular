# Staff structure screens: busy indicators

## Environment and scope

- Date: 2026-10-16
- Environment: local Angular workspace
- Branch: `development`
- Scope: Professional Structure, Academic Structure and Curriculum & Lesson Delivery
  (`features/staff-members/staff-{professional-structure,academic-structure,curriculum-delivery}`),
  new `shared/components/list-skeleton/list-skeleton.ts` and
  `shared/utilities/pending-counter.ts`

## Changes

- `pendingCounter()` counts in-flight requests. `track` is an RxJS operator that counts a
  request from subscribe until it completes, errors or is unsubscribed, and `active` is a
  signal. Several parallel loads therefore drive one flag. Before this, Professional Structure
  cleared `loading` only in `complete`, so a failed load left it stuck on `true`.
- `ListSkeleton` (`app-list-skeleton`) renders shimmer rows shaped like the record rows: a
  title line, a muted line and the row-action buttons. It is a `role="status"` region with
  `aria-busy="true"` and a screen-reader label. Inputs are `label`, `rows` (5) and `actions` (2).
- Each list shows the skeleton while `loading()` is true and the list is still empty. A
  reload after a save keeps the existing rows in place, the same rule as the staff category
  catalogue.
  - Professional: Staff Categories, master records (Job Families, Capabilities, Duties),
    Positions
  - Academic: master records, plus teaching assignments and class-teacher responsibilities
    on the per-staff route
  - Curriculum: Frameworks, Units, Lesson Plans, Delivery Logs, Syllabus Progress
- Professional and Academic share one record list across several tabs. That list is now
  cleared on tab switch, so the new tab shows the skeleton instead of the previous tab's rows.
- Every form's submit button shows `[loading]="saving()"` while its save request is in
  flight. Optimus disables a button while it is loading, which also stops a double submit.

## Code-review follow-up

A `/code-review` pass found the following, now fixed:

1. The list skeleton waited on unrelated reference lookups (job families, capabilities,
   sessions, statuses and others), so a truly empty list kept the shimmer until every lookup
   finished. Reference lookups are no longer counted. Curriculum now has one counter per list,
   exposed as `loading.frameworks()`, `loading.units()`, `loading.plans()`,
   `loading.deliveries()` and `loading.progress()`.
2. Tab-switch race: Professional and Academic now unsubscribe the previous tab's `loadSelected`
   request, so a late response can no longer fill the new tab with the old tab's rows.
3. Curriculum `selectFramework` clears `units`, and `loadUnits` cancels the previous
   framework's request, so the old framework's units are not shown, or editable, while the new
   ones load.
4. Professional checks the unfiltered lists (`categories()`, `masters()`, `positions()`) for
   the skeleton, so a status filter that matches nothing no longer shows the skeleton over
   loaded data.
5. `ListSkeleton` no longer sets `aria-busy="true"` on its `role="status"` region, which would
   have told screen readers to hold the announcement.
6. The components import `ListSkeleton` from the `@shared/components` barrel, after the
   `@core` imports.

Not changed: the review's double-submit-on-Enter finding. Browsers do not implicitly submit a
form whose submit button is disabled, and `[loading]` disables it.
