# Staff structure dialogs: input placeholders

## Environment and scope

- Date: 2026-10-17
- Environment: local Angular workspace
- Branch: `development`
- Scope: `features/staff-members/staff-professional-structure/professional-master-dialog`
  (`.ts`, `.html`) and `staff-category-dialog` (`.html`)

## Decision

- The Code, Name and Description inputs in the Add/Edit Job Family, Capability, Duty and Staff
  Category dialogs now show example placeholders. Before, they were empty.
- `ProfessionalMasterDialog` serves three master types, so it picks its placeholders from a
  `PLACEHOLDERS` map keyed by `StaffProfessionalMasterType`:
  - Job Family: `e.g. TEACH`, `e.g. Teaching`, "Describe the roles this job family covers"
  - Capability: `e.g. FIRST-AID`, `e.g. First Aid`, "Describe what this capability qualifies
    staff to do"
  - Duty: `e.g. BUS-DUTY`, `e.g. Bus Duty`, "Describe what this duty involves"
- Staff Category: `e.g. TEACH-STAFF`, `e.g. Teaching Staff`, "Describe who belongs to this
  category".
- These follow the `e.g. Weekly` style already used on Duty's Default frequency. Labels still
  name each field, so the placeholders are hints only.

### Code field formatting

- The Code input in both dialogs, and in the Add/Edit Position dialog, now uses the existing `FormText` `codeFormat` flag (already
  used by the policy definition form). Typing upper-cases the value and turns each run of spaces
  or dashes into one dash (`bus  duty` → `BUS-DUTY`); a trailing dash is dropped on blur. The
  saved value is the formatted one.

### Academic structure dialog

- `AcademicMasterDialog` (Session, Programme, Group, Section, Subject, Course Offering) gets
  the same treatment: a `PLACEHOLDERS` map keyed by `AcademicMasterType` for Code, Name and
  Description, plus `codeFormat` on Code. Examples follow the seeded data (`AY-2026-27`,
  `GRADE-01`, `GRADE-01-A`).
- Type-specific fields: Session start and end dates show `dd/mm/yyyy` (the `FormDate`
  default format), Section capacity shows `e.g. 40`, Course Offering curriculum version shows
  `e.g. 2026`. Programme Level already had `e.g. Secondary`.
