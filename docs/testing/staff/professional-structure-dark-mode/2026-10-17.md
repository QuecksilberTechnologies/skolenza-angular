# Staff Professional Structure dark-mode colour fixes

## Environment and scope

- Date: 2026-10-17
- Environment: local Angular workspace
- Branch: `development`
- Scope: `core/skolenza-preset.ts`, `src/styles.css`,
  `layout/app-aside-menu/app-aside-menu-item/app-aside-menu-item.ts`,
  `features/staff-members/staff-professional-structure/staff-professional-structure.html`,
  `features/authentication/pricing/pricing.html`,
  `shared/components/auth-split-card/auth-split-card.html`
- Trigger: user-approved fixes from a dark-mode screenshot review of the Professional Structure page

## Decisions

- **Dark form fields (global).** Aura's dark `formField` had a `surface.950` background (darker
  than the slate-900 card) and a `surface.600` border at 2.36:1, which fails the 3:1 boundary
  minimum in WCAG 1.4.11. `SkolenzaPreset` dark `formField` now uses background `surface.900`,
  border `surface.500` (3.75:1), hover border `surface.400`, and disabled background
  `surface.950`, so a disabled field is darker than an enabled one.
  This affects every outlined (default) field in dark mode. The `filled` variant keeps Aura's
  `filledBackground` tokens; nothing uses it today.
- **`.dark .auth-surface` removed.** Its only job was the same field lift on the auth pages. The
  global token makes it redundant, so the CSS block and the two `auth-surface` classes are gone.
- **Active aside item (dark).** A solid `bg-primary` fill was replaced by the system's branded tint:
  `dark:bg-primary-900/30` + `dark:text-primary-200!` (9.83:1), hover `primary-900/50` (8.82:1).
  Light theme is unchanged.
- **Activate / Deactivate buttons.** Changed from outlined to text buttons in all three lists
  (categories, masters, positions). The red or green label and icon stay; the bordered box that
  repeated on every row is gone. This affects both themes.
- **Not changed, by design.**
  - Save button: dark `primary.contrastColor` is `surface.900`, so the text is dark on
    `primary.400` (6.77:1). It passes.
  - Active section tab stays filled: the fill is what sets it apart from the outlined tabs.
  - Edit (secondary outlined) borders are `surface.700` on slate-900 (1.72:1), but the text label
    identifies the control, so 1.4.11 does not apply.
- **Locked-fix gate skipped.** The registry at `Skolenza.be/main_branch/LOCKED_FIXES.md`
  returned 404 (raw URL and `gh api`). The user told us to proceed without it.

## Code-review follow-up (same day)

The user ran `/code-review` and approved the fixes below.

- **Light-theme text and outlined labels (global).** Aura colours success and danger labels at
  `-500`: 2.28:1 and 3.76:1 on white, both under AA. Removing the Activate/Deactivate border left
  the label as the only cue. `SkolenzaPreset` light `outlined` and `text` now use `green.700`
  (5.02:1 on white, 4.57:1 on `green.100`) and `red.700` (6.47:1, 5.30:1 on `red.100`).
  `red.600` was rejected: 3.95:1 on the `red.100` active tint. Dark keeps Aura's `-400`.
- **Active aside hover.** `dark:hover:bg-primary-900/50!` now wins over the base
  `dark:hover:bg-zinc-800` regardless of the order Tailwind emits them in.
- **Primary stop overflow (pre-existing).** For light brands (`#ffeb3b`, `#00bcd4`)
  `accessiblePrimaryStop` falls back to 800, and `app.ts` set `activeColor` to the missing
  `{primary.1000}`. The active stop is now capped at 950. `skolenza_color.py ramp` crashed the
  same way (`KeyError: 1000`) and now applies the same cap.
- **Reviewed, not changed.** Brand-palette risk to `primary-200` on `primary-900/30` (the
  `palette()` tint and shade fractions keep it high for yellow, cyan and pink brands); disabled
  fields matching the `slate-950` canvas (fields sit in cards, the border still marks them); auth
  fields on the `slate-800` card (same as before; the border is now 3.07:1 instead of below 3:1).
