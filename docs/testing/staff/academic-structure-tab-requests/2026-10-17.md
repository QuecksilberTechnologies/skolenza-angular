# Academic structure: fetch only the selected tab

## Environment and scope

- Date: 2026-10-17
- Environment: local Angular workspace
- Branch: `development`
- Scope: `features/staff-members/staff-academic-structure/staff-academic-structure.ts` and its spec

## Problem

Visiting any tab under `/app/staff/academic-structure/` sent eight requests: teaching assignment
types, all six master lists (Session, Programme, Group, Section, Subject, CourseOffering), and then
the selected tab's list again. `ngOnInit` called `loadReferences()` up front to fill the dialog
pickers, whichever tab was open. The staff assignments page (`/app/staff/:staffMemberId/academic`)
made the same seven reference calls on load.

## Decision

- Opening a tab fetches only that tab's list (`loadSelected()`).
- Picker lists are fetched when a dialog opens, and only the ones that dialog uses:

  | Dialog                   | Lists fetched                          |
  | ------------------------ | -------------------------------------- |
  | Session, Programme, Subject | none                                |
  | Group                    | Session, Programme                     |
  | Section                  | Group                                  |
  | Course Offering          | Session, Group, Subject                |
  | Teaching assignment      | CourseOffering, Section, assignment types |
  | Class teacher            | Section                                |

- Lists are fetched again on every dialog open (no cache), so pickers are never stale after a
  save on another tab. The dialog opens once its lists arrive. If a request fails, the dialog
  doesn't open and the error shows as a toast.
- A save or status change reloads only the selected tab.

## Curriculum & Lesson Delivery

Same problem on `/app/staff/curriculum-delivery/*`: `loadAll()` on init fetched frameworks, lesson
plans, deliveries, syllabus progress, workflow statuses, teaching assignments, sessions and course
offerings. The auto-selected first framework also fetched its units, whichever tab was open.

### Decision

- Each tab fetches only what it shows:

  | Tab               | Requests                                        |
  | ----------------- | ----------------------------------------------- |
  | Frameworks        | workflow statuses, frameworks                   |
  | Units & Topics    | frameworks (picker), units of the picked one    |
  | Lesson Plans      | workflow statuses, frameworks, units, lesson plans |
  | Delivery Logs     | workflow statuses, lesson plans (row titles), deliveries |
  | Syllabus Progress | syllabus progress                               |

- Workflow statuses are a fixed lookup: fetched once, on the first tab that shows workflow badges.
- Picker lists load when their dialog opens: sessions (framework dialog), course offerings (unit
  dialog), teaching assignments (lesson plan dialog). A failed fetch shows a toast and the dialog
  stays closed.
- Saving, reviewing or deleting a delivery reloads deliveries only. Syllabus progress refreshes
  when its tab is opened.

### Results

- `bun run test -- --include "src/app/features/staff-members/staff-curriculum-delivery/**/*.spec.ts"`:
  4 files, 28 tests passed. New tests: Frameworks tab sends only statuses and frameworks, Syllabus
  Progress tab sends only progress, Units & Topics loads the first framework's units, the framework
  dialog fetches sessions on open.
- `ng lint` and `oxfmt --check` on the changed files: passed.
- Not verified in a running browser.

### Follow-up: units without topics

The Units & Topics tab threw `TypeError: Cannot read properties of undefined (reading 'length')`
at `staff-curriculum-delivery.html:85` (`unit.topics.length`). The units response leaves `topics`
out for a unit that has none, and the error aborted rendering of the remaining rows.
`loadUnits()` now defaults `topics` to `[]` for every unit, which also covers
`topicsForTeachingAssignment()`. New test: a unit without topics gets an empty list. Curriculum
specs: 4 files, 29 tests passed. Not verified in a running browser.
