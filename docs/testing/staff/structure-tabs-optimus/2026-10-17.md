# Staff structure pages: Optimus tabs

## Environment and scope

- Date: 2026-10-17
- Environment: local Angular workspace
- Branch: `development`
- Scope: `features/staff-members/staff-professional-structure`, `staff-academic-structure`,
  `staff-curriculum-delivery` (`.html`, `.ts`), the professional structure `.spec.ts`, and the
  removal of `shared/components/tab-bar`

## Bug

On `/app/staff/professional-structure/staff-categories` the list showed Staff Categories, but
the Positions button stayed filled. `app-tab-bar` switched styling through `[outlined]` on the
Optimus `pButton` directive. That input has no setter: the directive writes
`p-button-outlined` once at init and never removes it, so the first-rendered tab kept the
filled style after route changes. `aria-current` was correct; only the styling went stale.

## Decision

- Retired the custom `app-tab-bar` (added in `fb6f32f`). It duplicated Optimus `p-tabs`, which
  the repo already uses for route-driven sections (payroll, settings).
- The three staff structure pages now use `p-tabs` / `p-tablist` / `p-tab`. Filters and the
  Add button sit in a flex row beside the tablist.
- Navigation goes through `(valueChange)="openTab($event)"`, not `routerLink` on `p-tab`.
  `p-tab` calls `preventDefault()` on Enter/Space and fires no click, so `routerLink` on a
  non-anchor host would not navigate from the keyboard.
- `openTab()` now takes the raw `p-tabs` value (`string | number | undefined`) and ignores
  values that are not a known tab.
- Each list sits in one `p-tabpanel` bound to the selected tab, so the selected tab's
  `aria-controls` and the panel's `aria-labelledby` resolve. axe skips `aria-controls` on
  unselected tabs (`aria-selected="false"`).
- `SelectButton` was rejected: it is a value control (`aria-pressed`), not navigation.

## Code review follow-up (same day)

`/code-review` raised ten findings on the first version. All were addressed:

- **Shared `app-route-tabs`** (`shared/components/route-tabs`) replaces the three inline copies
  of the `p-tabs` markup. Inputs: `tabs` (`RouteTab<T>`: `id`, `label`, `route`), `selected`,
  `ariaLabel`. Content marked `toolbar` sits beside the tabs; the rest renders in the panel.
  The wrapper owns navigation (`['..', route]` relative to the page's route), so the pages'
  `openTab()` was removed in professional and academic structure. Curriculum keeps a typed
  `openTab(tab: CurriculumTab)` for its post-dialog switch to Delivery Logs.
- **Selection sync:** `activeTab` is a `linkedSignal` of `selected`, two-way bound to `p-tabs`.
  On click the strip and panel follow at once (no blank panel while navigation runs). If
  `navigate` resolves `false` or rejects, the wrapper writes `selected` back into the `p-tabs`
  model through `viewChild`; resetting the signal alone failed in tests because the binding
  had never pushed the clicked value.
- **Accessible name:** the tab list gets `aria-label` through `[pt]="{ tabList: … }"`.
- **Dangling `aria-controls`:** an empty, hidden `p-tabpanel` stands in for each unselected tab,
  so every tab's `aria-controls` resolves.
- **Divider:** the tab and toolbar row has a `border-b` again; the tablist's own border is
  removed through `pt` so there is one line.
- **Curriculum lookup:** an `isCurriculumTab` type guard replaces `find(...)?.id`.
- **Specs:** `setupRouting()` helper in the professional spec; click-path tests in the page
  spec and in `route-tabs.spec.ts` (click navigates, same tab does nothing, panel stays
  visible, failed or rejected navigation restores the tab, every `aria-controls` resolves).

Also on request: the description tooltips on professional and academic structure rows now use
`[showDelay]="300"`, the repo's existing tooltip delay.
