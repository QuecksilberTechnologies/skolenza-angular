## Decisions

- **Landmarks.** The page's inner `<main>` became a `<div>`; `layout/layout.html` already owns `<main>`.
- **Tabs.** Rendered as `<button pButton>` from `STRUCTURE_TAB_ROUTES` with
  `aria-current="page"` on the selected tab. The status filter moved out of `<nav>` and gained
  `appendTo="body"`.
- **Permissions.** Gated through `FeaturePageStore.canPerformOrUnknown('STAFF_DIRECTORY', op)`,
  the boundary `module-operation-routes.ts` maps these endpoints to. Add form needs `Add`; Edit,
  Activate and category status toggles need `Update`; master and position Deactivate need `Delete`
  (their DELETE endpoints soft-deactivate). Rows with no permitted action show no menu.
- **Row actions.** Per-row Edit/Deactivate buttons replaced by one `app-table-action-button` per row
  (`aria-label="Actions for <name>"`) opening a shared `p-tieredmenu` popup.
- **Validation.** Required fields carry a visual `*`; a save attempt with missing values sets
  `showErrors` and shows inline errors (`aria-invalid` + `aria-describedby` on text inputs) instead
  of returning silently. `resetForm()` and Edit clear it.
- **Focus.** Edit moves focus to the form heading (`tabindex="-1"`) after render.
- **Surfaces and tokens.** Inner panels use `rounded-card border-zinc-200 dark:border-zinc-800`
  (grouping inside the page `p-card`, not raised surfaces). Muted text `zinc-500/400`, names
  `zinc-900/50`. Page shell is `h-[calc(100vh-4.6rem)] overflow-y-auto`; the form is
  `lg:sticky lg:top-4`, and the list takes full width when the form is hidden.
- **Status chip.** All three lists show an Active/Inactive chip with `pi-check-circle` / `pi-ban`.
  Contrast checked with `skolenza_color.py`: `#15803d` on `#f0fdf4` 4.79:1, dark `#4ade80` on
  green-900/30 over slate 8.60:1. Error text `#dc2626` on white 4.83:1, dark `#f87171` on
  `#0f172a` 6.45:1.
- **Copy.** Headings, loading labels, empty states and tab labels come from one `TAB_NOUNS` map
  ("Add Job Family", "No job families yet. Add the first one with the form."). Cancel shows only
  while editing. Master descriptions truncate with a tooltip, and the trailing `·` is gone when
  a description is empty. Textareas use `rows="3"`.
- **Not done.** The forms are still template-driven (`ngModel`). Moving to Signal Forms is a
  separate refactor.

## Follow-up: add/edit forms moved into dialogs

- **Decision.** Dialog, not a new page, matching the app's add/edit convention (`DialogService`
  manage dialogs, e.g. Departments). The forms hold 3 to 6 fields plus two checklists, and a dialog
  keeps the list in view.
- **Components** (under `staff-professional-structure/`):
  `professional-master-dialog/` (Job Family, Capability, Duty; Default frequency for Duty only),
  `staff-category-dialog/`, `staff-position-dialog/`. Each is a Signal Form with a colocated zod
  schema, built from the shared `app-form-*` wrappers. Model types use `z.input` because the
  required-id refines narrow `null` out of `z.infer`.
- **Page.** An `Add <noun>` button (needs `Add`) sits beside the status filter. Row-menu Edit opens
  the same dialog prefilled. The lists take the full width; the side form, sticky layout,
  `showErrors` flag and focus-on-edit code are gone. Saves close the dialog with `true`, and the page
  reloads the list (plus reference data after a master save).
- **Behaviour kept.** Inactive-but-linked job families, categories, capabilities and duties stay
  visible and locked. The shared `app-form-select` / `app-form-multiselect` wrappers gained an
  `optionDisabled` input for this. Edits keep fields the forms do not show (certification flags,
  display order, description, department).
- **Behaviour changed.**
  - A category whose job-family mapping call fails after the category saved now closes the dialog
    and refreshes the list, so a retry cannot create a duplicate.
  - Changing a position's category no longer silently clears the job family. A job family the new
    category does not allow fails validation ("Choose a job family this category allows"), and the
    job family select stays disabled until a category is picked.
  - Linked capabilities and duties list first, in saved order; that order is what gets saved.
  - Codes are typed as entered; the wrapper's `codeFormat` (dashes) was not used because existing
    codes use underscores.
- **Template-driven forms.** None left on this page except the status filter `ngModel`, which is a
  list filter, not a form.

## Follow-up: Position dialog redesign

- Locked fixes: `LOCKED_FIXES.md` still 404 (raw URL and `gh api`); skipped with explicit user
  approval for this request.
- **Own header.** The Position dialog draws its own header: briefcase icon tile, "Add Position" /
  "Edit Position" `<h2>`, a one-line description, and a text close button (`aria-label="Close"`;
  Escape still closes). `openManageDialog` gained an optional `titleId`: when set, the built-in
  header is hidden, the dialog is labelled by that id (`aria-labelledby`), and `.p-dialog-content`
  becomes a non-scrolling flex column so the component owns the scroll region.
- **Layout.** Header and footer stay pinned; the body scrolls. Basic fields keep the two-column
  grid with placeholders. Capabilities and duties each get a section with an icon tile, title and
  description, then a two-column grid (`sm:`) of bordered checkbox cards. Selected cards take the
  branded tint.
- **Required / Optional pill.** Replaces the per-row "Mandatory" checkbox. It appears on selected
  rows and toggles `isMandatory`; the visible text says the current state, and an `sr-only` prefix
  names the row so each button's accessible name is unique and contains its visible label.
- **Footer.** `app-form-action-bar` (dialog variant) now projects leading content; the Position
  dialog puts the Active checkbox there. Submit reads "Create position" or "Save changes".
- **No wrapping.** The dialog widens from `48rem` to `56rem`, so the longest seeded names fit on
  one line. Names that still overflow (narrow viewports) `truncate` with a `pTooltip` of the full
  name; the checkbox's accessible name stays complete.
- Contrast (brand `#4287f5`): pill `primary-700` on `primary-100` 4.84:1, dark `primary-50` on
  `primary-800` 8.28:1, optional `zinc-600` on `zinc-100` 7.03:1, dark `slate-300` on `slate-800`
  9.85:1. All pass AA.
