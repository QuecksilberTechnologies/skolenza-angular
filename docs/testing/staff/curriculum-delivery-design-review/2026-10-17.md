## Decisions

- **Tabs.** Shared `app-tab-bar` with URL tabs (`curriculum-delivery/:tab`): `frameworks`,
  `units-topics`, `lesson-plans`, `delivery-logs`, `syllabus-progress`. An unknown segment is
  replaced with `frameworks`. The tab id is the URL segment (`CURRICULUM_TABS`).
- **Toolbar.** The curriculum framework picker moved into the tab bar for Units & Topics and Lesson
  Plans. Add buttons per tab: Add Curriculum Framework, Add Unit (once a framework is picked), Add
  Topic (once the framework has units), Add Lesson Plan, Record Lesson Delivery.
- **Workflow status.** Shown with the shared `app-status-badge`: Draft neutral `pi-pencil`,
  Submitted info `pi-send`, Approved success `pi-check-circle`, Rejected danger `pi-times-circle`.
  The label is the API's status name. Frameworks also show an "Inactive" badge when
  `isActive` is false; the list never showed it before.
- **Row menu.** One `app-table-action-button` per row opening a shared `p-tieredmenu`:
  - Draft or Rejected: Edit, Submit, Delete
  - Submitted: Approve, Reject
  - Approved lesson plan: Record Delivery (opens the delivery dialog with the plan preselected)
  - Approved framework or delivery: no menu. The API (`StaffCurriculumDeliveryApi`) has no
    deactivate, new-version or detail call for approved records.
  - Unit: Edit, Add Topic (preselects the unit), Delete. Topic: Edit, Delete. Topics no longer
    open the edit form on click; the menu does.
- **Delete wording.** "Remove" became "Delete". The DELETE endpoints carry no soft-delete note,
  and the existing confirm copy says records in use must be removed first, which reads as a hard
  delete. The confirm dialog is unchanged.
- **Permissions.** `FeaturePageStore.canPerformOrUnknown('STAFF_DIRECTORY', op)`, the module
  `module-operation-routes.ts` maps every curriculum endpoint to. POST is `Add`; PUT, including
  every `/review` call (Submit, Approve, Reject), is `Update`; DELETE is `Delete`. Menu items are
  hidden per operation; a row with nothing permitted shows no menu; Add buttons need `Add`.
- **Dialogs.** All five forms moved into `DialogService` dialogs built as Signal Forms with
  colocated zod schemas (`z.input` model types) and the shared `app-form-*` wrappers. Units and
  topics share one dialog (`kind: 'unit' | 'topic'`) because only the parent differs (course
  offering vs unit). Dates use `app-form-date` (`Date | null`) and are sent as local `yyyy-MM-dd`
  via `localDateKey`; saved dates load through `fromDateKey`.
- **Validation.**
  - Required, as before: framework code, name, authority, version, effective from; unit and topic
    code and name; lesson plan date and objectives; delivery date and coverage notes.
  - Newly required (foreign keys the old forms sent as `0` when left empty): framework academic
    session, unit course offering, topic unit, lesson plan teaching assignment, delivery lesson
    plan.
  - Effective to must be on or after effective from. Sequence and planned periods are whole
    numbers of at least 1. Topic completion must be 0 to 100.
- **Behaviour kept.** Lesson plan topics are limited to the chosen assignment's course offering,
  and topics outside it are dropped on save (previously on assignment change). Picking a delivery
  plan resets coverage to that plan's topics at 100%. A new delivery defaults to the local calendar
  day. Fields the dialogs do not show (descriptions, parent unit, `isActive` on units, topics,
  plans and deliveries) are kept from the record.
- **Behaviour changed.** Recording a delivery from an approved plan no longer switches to the
  Delivery Logs tab; it opens the dialog in place and refreshes deliveries and progress after save.
  An edited delivery whose plan is no longer approved still lists that plan.
- **Copy.** Title-case headings ("Add Curriculum Framework", "Record Lesson Delivery"), every
  submit button says "Save", the draft state is explained in the plan and delivery dialogs,
  empty states name the next step for users who can add. The framework meta line shows
  "Version 2026.1" instead of repeating the status.
- **Tokens.** Page shell `h-[calc(100vh-4.6rem)] overflow-y-auto`; list `rounded-card` with
  `zinc-200/800` borders; muted text `zinc-500/400`; names `zinc-900/50`. Syllabus progress bars
  now expose `role="progressbar"` with value and label.
- **Template-driven forms.** None left except the framework picker `ngModel`, which is a list
  filter.
