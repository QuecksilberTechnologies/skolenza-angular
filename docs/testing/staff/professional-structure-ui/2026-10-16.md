## Changes

1. Dark mode: the list and form panels hard-coded `bg-white`, so in `.dark` the row names,
   form heading and field labels were light text on white and could not be seen. The panels
   now use the same pattern as the staff category catalogue:
   `border-gray-200 bg-white dark:border-zinc-700 dark:bg-zinc-900`. Rows use
   `border-gray-200 last:border-b-0 dark:border-zinc-700`. Muted text adds
   `dark:text-zinc-400`, and the section nav border is tokenised the same way. The category
   Active/Inactive chip gets dark variants (`dark:bg-green-950 dark:text-green-300`,
   `dark:bg-zinc-800 dark:text-zinc-300`).
2. Deactivate calling `deleteMaster` / `deletePosition`: the user confirmed that the backend
   DELETE endpoints soft-deactivate (`isActive = false`). Behaviour is unchanged. A comment
   in `confirmMasterActive` records this.
3. Confirm dialog: the accept button is `p-button-danger` when deactivating and stays
   `p-button-primary` when activating.
4. Confirm dialog message: Optimus `p-confirmDialog` renders `message` through
   `[innerHTML]`, so the record name is HTML-escaped (`escapeHtml`) before it goes inside
   `<strong>`. `escapeHtml` later moved to `shared/utilities/escape-html.ts` (see the Academic
   Structure record of the same date).
