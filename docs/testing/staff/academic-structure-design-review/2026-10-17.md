## Decisions

- **Tabs.** `app-tab-bar` with URL tabs (`sessions`, `programmes`, `groups`, `sections`,
  `subjects`, `course-offerings`). An unknown segment is replaced with `sessions`. Labels are
  plural ("Course Offerings", which fixes the old "CourseOffering"); dialog headers use the
  singular ("Add Course Offering"). The status filter (All / Active / Inactive) and the
  `Add <noun>` button are projected into the tab bar.
- **Permissions.** `FeaturePageStore.canPerformOrUnknown('STAFF_DIRECTORY', op)`, the boundary
  `module-operation-routes.ts` maps every academic-structure endpoint to. Add needs `Add`; Edit and
  Activate need `Update`; Deactivate (DELETE, a soft deactivate) needs `Delete`. Rows with no
  permitted action show no menu.
- **Rows.** `app-status-badge` (Active `success` + `pi-check-circle`, Inactive `neutral` +
  `pi-ban`), one `app-table-action-button` per row named for the record, and a shared
  `p-tieredmenu` with Edit / Deactivate / Activate. **Activate is new**: before, an inactive
  record had no way back. It confirms, then saves the record with `isActive: true` through the
  same PUT the edit uses (`SaveAcademicMaster`, `SaveTeachingAssignment` and
  `SaveClassTeacherAssignment` all carry `isActive`). Descriptions truncate with a tooltip, and
  there is no trailing `·` when a description is empty.
- **Dialogs (Signal Forms + zod, `z.input` model types, `app-form-*` wrappers).**
  - `academic-master-dialog`: one dialog for all six types. Code and Name required.
    - Session: start and end dates, both required, end on or after start.
    - Programme: Level.
    - Group: Session and Programme.
    - Section: Academic group and Capacity (a whole number, 0 or more).
    - Course Offering: Session; then Academic group, disabled until a session is picked, limited
      to that session's groups, and flagged if a session change strands it; then Subject and
      Curriculum version.

    An edit starts from the saved record so fields the dialog does not show survive. A create
    sends no `id` key; the API reads a present id as an update.
  - `teaching-assignment-dialog`: Course offering, Section (disabled until an offering is picked,
    limited to the offering's group), Assignment role, Contribution % (whole number, 1 to 100) and
    Effective from are required. Effective to must be on or after from.
  - `class-teacher-dialog`: Section and Effective from required; Effective to must be on or after
    from.
  - Dates use `app-form-date` (`p-datepicker`) instead of the native `type="date"` input. Values
    convert with `fromDateKey` / `localDateKey`, so the API still receives local calendar
    `yyyy-mm-dd` strings.
- **Staff-member mode.** The two panels are bordered `rounded-card` sections with an `h2`
  header, an Add button (`Add Teaching Assignment`, `Add Responsibility`), and the same badge and
  row-menu treatment. The inline forms are gone.
- **Shell and tokens.** The page shell is `h-[calc(100vh-4.6rem)] overflow-y-auto`, the panels
  use `rounded-card border-zinc-200 dark:border-zinc-800`, and text uses zinc tokens. Empty states
  name the next step when the user can add ("No sessions yet. Use Add Session to create one.").
- **Behaviour changed.**
  - Saving a master no longer sends type-irrelevant blanks as empty strings: blank Level and
    Curriculum version go as `undefined`.
  - Teaching and class-teacher assignments now validate required fields in the browser; before,
    the browser sent whatever the form held.
  - The teaching-assignment role and section are required, and the section must belong to the
    offering's group.
