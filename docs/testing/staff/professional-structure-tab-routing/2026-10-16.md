# Staff Professional Structure tab routing

## Environment and scope

- Date: 2026-10-16

  `features/staff-members/staff-professional-structure` (`.html`, `.ts`, `.spec.ts`)

## Decision

Each tab on the Staff Professional Structure page now has its own URL, so tabs can be
bookmarked, shared, refreshed and reached with browser back/forward:

| Tab              | URL                                                |
| ---------------- | -------------------------------------------------- |
| Job Families     | `/app/staff/professional-structure/job-families`   |
| Staff Categories | `/app/staff/professional-structure/staff-categories` |
| Capabilities     | `/app/staff/professional-structure/capabilities`   |
| Duties           | `/app/staff/professional-structure/duties`         |
| Positions        | `/app/staff/professional-structure/positions`      |

- The route is `professional-structure/:tab`, so one component instance serves every tab.
  Reference lookups load once and are not refetched when the tab changes.
- The bare `professional-structure` path redirects to `job-families`. Existing links,
  such as the Staff Directory button, keep working.
- An unknown `:tab` segment is replaced with `job-families` using `replaceUrl`.
- Tab buttons call `openTab()`, which navigates. The `paramMap` subscription calls
  `selectTab()`, which cancels the previous request, resets the form and loads the list.
