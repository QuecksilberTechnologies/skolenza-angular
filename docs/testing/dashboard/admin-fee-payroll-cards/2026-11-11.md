# Admin dashboard fee collection and payroll cards

## Environment and scope

- Date: 2026-11-11
- Environment: local Angular workspace
- Branch: `development_deepesh_new`
- Scope: `features/dashboard/dashboard-admin` (`dashboard-admin.ts`, `dashboard-admin.html`,
  new `fee-collection-card/`, new `payroll-summary-card/`)

## Decision

Two cards added to the admin dashboard, first in the widget grid, for a stakeholder demo.
Both show **static sample data** and carry a visible `Sample data` tag until the backend APIs exist.

- **Fee Collection** (`app-fee-collection-card`, spans two columns from `md`):
  expected, collected and pending amounts; overall collection percentage with a progress bar;
  paid, partially paid and not paid student counts; then one row per location with collected of
  expected, percentage bar, the three status counts and pending amount.
- **Staff Payroll** (`app-payroll-summary-card`): current month paid and pending staff counts,
  paid and pending amounts; month-wise rows (paid of total staff, percentage bar, payout); total
  payout across listed months; link to `/app/payroll`.
- Data lives in `SAMPLE_LOCATIONS` / `SAMPLE_MONTHS` constants typed by exported
  `LocationFeeSummary` / `MonthlyPayrollSummary`. When the APIs land, replace the constants with a
  store (`rxResource` in `AdminDashboardStore` or a card store, as in `locations-card`) and drop
  the `Sample data` tag.
- Percentage colour reuses `shared/utilities/progress-tone.ts`; every percentage is also printed
  as text, and each bar has `role="progressbar"` with an `aria-label`.

## Code review fixes

- Payroll card renders only when `canAccessOrUnknown('Payroll')`, the same key `hasModulePermissionGuard('Payroll')` uses on the routes its link opens.
- Amounts go through `currency: (currencyKey() | currencySymbol)`. Each card takes a `currencyKey` input (default `INR`) that the API should supply, so the hard-coded `'INR'` is gone.
- Sample period moved off February 2026 (now derived from today, see below).
- Total payout label names its span: `Total payout (4 months)`.
- Amount tiles no longer `truncate`; they wrap (`wrap-anywhere`) so narrow columns never hide a figure.
- Sample cards show in every environment, production included: user decision 2026-11-11 for the demo. The `Sample data` tag stays the only marker; replace the constants with API data before real use.
- Colour bands: kept `progressTone` (>= 80 green, >= 70 amber, else red). No finance bands are defined, and one app-wide tone rule beats invented thresholds; the percentage is always printed beside the colour.
- Deferred: empty-month guard, shared `percentOf` and stat-tile extraction. Revisit when the APIs land.

## Second review fixes

- Payroll gate uses strict `canAccess('Payroll')`; `canAccessOrUnknown` let salary figures flash before the permission matrix loaded.
- New `shared/utilities/percent-of.ts` (with spec) used by both cards: floors (99.5% reads 99%, never a false 100%), clamps to 0-100 so `aria-valuenow` stays valid. Pending amounts and counts clamp at 0.
- Sample data held in plain fields, not `computed()`.
- Location name truncates (`min-w-0`).
- Payroll footer pinned to the card bottom through `[pt]` on `p-card` body/content.
- Fee period defaults to the current month; payroll months are the current month and the three before it.
- Fee card stays ungated: no fee module key exists yet. Add a gate when the fee API lands.
