Skolenza Design System

Design tokens, interaction rules and Angular CDK patterns for custom-built Skolenza components - the ones Optimus UI does not ship, or ships in a shape we cannot use. Every value below is derived from what the app already renders (src/styles.css, core/skolenza-preset.ts, and the class frequencies across src/app/**/*.html), so adopting it does not restyle the product.

Where each layer lives

Layer Owner Use it for
--p-* Optimus UI / Aura preset (core/skolenza-preset.ts) Palette + component tokens. Source of truth for colour. Custom components read these, never re-declare them.
--ax-* This guide, declared in src/styles.css Geometry and motion: radius, elevation, control height, duration, easing. Fixed in px so the 13px root scale cannot drift them.
Tailwind utilities Tailwind v4 + @openng/optimus-ui-tailwindcss Layout, spacing, typography in templates. First choice in feature code.
Component CSS The component's own .css Only what a utility cannot express: overlay panels, keyframes, ::part-style internals. Budget: warn at 4kB, error at 8kB per stylesheet.

Build a custom component only when Optimus cannot do the job. The order is: Optimus component → Optimus component wrapped in shared/components/ → CDK primitive + this token set. A hand-rolled overlay costs you focus management, scroll strategy, RTL and ARIA that CDK already solved.

The 13px root scale

html { font-size: 0.8125rem } in src/styles.css. One rem is 13px, not 16px. Every Tailwind rem utility in the app is therefore ~19% smaller than its documented value.

Utility rem Renders at Utility rem Renders at
text-xs 0.75 9.75px p-1 / gap-1 0.25 3.25px
text-sm 0.875 11.38px p-2 / gap-2 0.5 6.5px
text-base 1 13px p-3 / gap-3 0.75 9.75px
text-lg 1.125 14.63px p-4 / gap-4 1 13px
text-xl 1.25 16.25px p-6 1.5 19.5px
text-2xl 1.5 19.5px p-8 2 26px

Rule: inside a custom component's own CSS, express geometry (control height, icon box, radius, overlay offset, hit area) in px or in --ax-* tokens. Use rem only for type, where scaling with the root is the point. Mixing a 16px-mental-model rem into a 13px root is the single most common sizing bug in this repo.

--p-content-border-color, --p-primary-color, --p-surface-* and friends already resolve per theme and per .dark. Never hardcode a hex in a custom component - the Appearance panel rewrites the primary ramp at runtime from ACCENT_COLORS (shared/interfaces/settings.ts).

Color

Neutrals are zinc in light mode and slate in dark mode (skolenza-preset.ts maps the whole surface ramp per scheme). Primary is user-chosen at runtime. Semantics come from the Optimus palette. Templates keep their dark:*-zinc-* utilities: src/styles.css remaps the zinc scale to slate under .dark.

Typography

Inter, loaded from Google Fonts in src/styles.css. One family, four weights. No secondary display face.

Role Utility Size @13px root Weight Line height

Subsection, dialog header text-base font-medium 13px 500 1.4

Observed usage across the app: text-sm 571×, text-xs 383×, text-base 115×. Two sizes carry nearly everything - resist adding a third inside one component.

  • Letter spacing: default everywhere except headings ≥ 19px, which take tracking-tight; all-caps micro-labels take tracking-wide.
  • Numbers in tables and KPIs: tabular-nums, so columns do not jitter.
  • Truncate with truncate (single line) or line-clamp-2; never let a name reflow a table row.
  • Minimum rendered size is text-xs (9.75px). Anything smaller fails readability review - raise the root, don't shrink the text.

Borders & radius

Border

  • Width is always 1px. A 2px border means "focus ring", nothing else.
  • Style is always solid. Dashed is reserved for drop targets and empty placeholders (border-dashed + muted colour).
  • Colour is --ax-border-color (zinc-200 / slate-800). A strong border (control outline, zinc-300 / slate-700) is for interactive controls that must read as editable: inputs, select triggers, outlined buttons.
  • Dividers inside a surface use the same 1px border, never a shadow.

Optimus cards are already pinned at --p-card-border-radius: 0.8rem (10.4px). A custom card sitting next to one should use 10px, not 12px - the .ax-card demo below does.

Nesting rule: an inner radius is the outer radius minus the gap between them. A 6px row inside a 12px panel with 6px padding lines up; a 12px row inside it does not.

Sizing & hit targets

Target sizes

  • 24×24 CSS px absolute minimum for any pointer target (WCAG 2.5.8 AA). A 28px control already clears it; a 16px icon button does not - pad it to 28px.
  • 40×40 for anything primarily used on touch (mobile nav, bottom sheets, calendar cells on small screens).
  • Adjacent targets keep ≥4px of clear space, or the spacing exemption does not apply.
  • Extend the hit area without growing the visual with padding, or a ::after inset overlay - never with transform: scale().

Widths

  • Overlay panel: min-width = trigger width, max-width: min(92vw, 420px).
  • Dialog: sm 360px, md 480px, lg 640px, xl 840px; always max-width: 92vw, max-height: 88vh with a scrolling body.
  • Drawer: 320px / 420px / 560px, full width below sm.
  • Text content caps at max-w-prose (~65ch) - long paragraphs never span a wide dialog.

Icons

Three sources are installed: pi pi-* (Optimus/PrimeIcons, the default), @openng/icons, and lucide-angular. Pick one per component and do not mix visual styles inside a single surface.

Motion (Angular 22 native animations)

@angular/animations is deprecated as of v20.2 and is not a dependency of this app. All motion is CSS, triggered by classes, @starting-style, or the native animate.enter / animate.leave template bindings.

TokenValueUse
--ax-duration-fast150msHover, active, colour, opacity, focus ring
--ax-duration-base200msOverlays, tooltips, menus, expand/collapse, tab indicator
--ax-duration-slow300msDrawer, dialog, route-level transitions
--ax-ease-entercubic-bezier(0,0,.2,1)Anything appearing (decelerate)
--ax-ease-exitcubic-bezier(.4,0,1,1)Anything leaving (accelerate)
--ax-ease-standardcubic-bezier(.4,0,.2,1)State changes on a persistent element
  • Leave is faster than enter. Enter at the token duration, leave at ~0.75× it. Nobody waits for a dismissal.
  • Animate opacity and transform only. Never animate height/width directly - use the grid-template-rows: 0fr → 1fr trick for auto height.
  • Travel distance: 4px for tooltips, 6-8px for menus and popovers, 12px for toasts, full-axis slide for drawers.
  • No entrance animation on first paint of a list - it reads as jank. Animate only what the user's action caused.

Overlay enter / leave

<!-- template -->
@if (isOpen()) {
  <div class="ax-panel" animate.enter="ax-panel-in" animate.leave="ax-panel-out">
    <ng-content />
  </div>
}
/* component css */
.ax-panel-in  { animation: ax-in var(--ax-duration-base) var(--ax-ease-enter); }
.ax-panel-out { animation: ax-out 150ms var(--ax-ease-exit) forwards; }

@keyframes ax-in  { from { opacity: 0; transform: translateY(-6px) scale(.98); } }
@keyframes ax-out { to   { opacity: 0; transform: translateY(-4px); } }

@media (prefers-reduced-motion: reduce) {
  .ax-panel-in, .ax-panel-out { animation-duration: 1ms; }
}

Keep the reduced-motion duration at 1ms rather than none. animate.leave waits for the animation to finish before removing the element; killing the animation outright can strand the node.

Expand / collapse without a height animation

.ax-collapsible { display: grid; grid-template-rows: 0fr; overflow: hidden;
                  transition: grid-template-rows var(--ax-duration-base) var(--ax-ease-standard); }
.ax-collapsible.is-open { grid-template-rows: 1fr; }
.ax-collapsible > .content { min-height: 0; }

Staggered lists

@for (row of rows(); track row.id; let i = $index) {
  <li class="row" [style.--i]="i">{{ row.name }}</li>
}
.row { transition: opacity var(--ax-duration-base) var(--ax-ease-enter);
       transition-delay: calc(30ms * var(--i)); }
.row  { @starting-style { opacity: 0; transform: translateX(-6px); } }

Cap the stagger at ~8 items (240ms); past that it reads as lag.

  • Form grid: grid grid-cols-1 md:grid-cols-2 gap-4; a full-width field takes md:col-span-2.

States

Every interactive custom component implements all eight. A component with only hover and disabled is unfinished.

StateVisualImplementation
Rest Surface + 1px border, no shadow beyond its elevation level -
Hover Background steps one surface level (zinc-50 / slate-800); borders darken one step. Never move the element. :hover, 150ms background transition. Pointer devices only: wrap in @media (hover: hover).
Focus (keyboard) 2px primary outline, 2px offset, on top of the resting border :focus-visible only - never :focus. Inputs instead use a 1px inset ring (--p-inputtext-focus-ring-*) so the field does not jump.
Active / pressed Background one step deeper than hover; no scale transform :active, no transition (instant feedback)
Selected / checked Primary-soft background + medium weight, plus a non-colour marker (check, dot, left bar) [aria-selected] / [aria-checked] attribute selectors, not a class
Disabled opacity: .55, cursor: not-allowed, no hover response Real disabled on natives; aria-disabled="true" + no handler on composites. Keep disabled items focusable in menus and toolbars so keyboard users can discover them.
Loading Skeleton for first load; 16px spinner + aria-busy for in-place refresh; button keeps its width and swaps the leading icon Shimmer 1.4s; announce with aria-live="polite" if it exceeds ~1s
Error Danger border + message below, 11px. Message text is specific, never "Invalid input". aria-invalid="true" + aria-describedby pointing at the message id

Never remove the focus ring. outline: none without a replacement is an accessibility defect and fails ESLint's template a11y rules the moment it reaches a template binding.

Accessibility

The bar is WCAG 2.2 AA and zero AXE violations. ESLint runs angular.configs.templateAccessibility on every .html; failures there are bugs, not style nits.

Keyboard contract per pattern

PatternKeysFocus
Menu / dropdown Enter/Space/↓ open, ↑↓ move, Home/End, type-ahead, Esc close, Tab closes and moves on Roving tabindex inside; focus returns to the trigger on close
Dialog Esc closes, Tab cycles inside Focus traps; initial focus on the first control (not the close button); restores to the opener
Drawer Same as dialog when modal; no trap when it is a non-modal side panel Non-modal: focus moves in but Tab escapes naturally
Tabs ←→ move, Home/End jump; automatic activation Only the active tab is tabbable; panel is tabindex="0" if it scrolls
Tooltip Shows on focus as well as hover; Esc dismisses Never focusable itself; content must be hoverable (WCAG 1.4.13)
Data table Tab reaches interactive cells; sort buttons are real buttons aria-sort on the sorted header; row actions reachable without hover
Date picker Arrows move a day, PgUp/PgDn a month, Esc closes Grid roving tabindex; the focused day is the only tab stop

Non-negotiables

  • Contrast: 4.5:1 body text, 3:1 for ≥19px bold text, UI borders and icons that carry meaning. Muted zinc-500 on white is 4.6:1 - fine; zinc-400 on white is not, which is why dark mode uses slate-400 and light mode zinc-500.
  • Focus visibility: a 2px ring with 2px offset against the adjacent colour at ≥3:1 (WCAG 2.4.11).
  • Announce async change: CDK LiveAnnouncer for "12 results", "Saved", "3 rows selected".
  • Name every control: visible label preferred; icon-only gets aria-label; a required field's label carries a visible * (zod-driven validation no longer sets the native required attribute).
  • Respect reduced motion in every component that animates.
  • Colour is never the only channel - pair it with text, icon or shape.
  • Zoom to 200% without horizontal scroll, and reflow at 320px width.
// Announce a result count after a filter
private readonly announcer = inject(LiveAnnouncer);
this.announcer.announce(`${count} staff members found`, 'polite');

CDK Overlay

Everything that floats - menu, popover, select panel, tooltip, dialog, drawer - is a CDK overlay. Skolenza has three house rules that CDK's defaults do not cover.

1. Use the shared position set

CARD_OVERLAY_POSITIONS in shared/utilities/overlay.ts gives the standard flip order (below → above → end-aligned below → end-aligned above) with the 6px trigger gap already applied. 

<ng-template
  cdkConnectedOverlay
  appRepositionOnResize
  [cdkConnectedOverlayOrigin]="trigger"
  [cdkConnectedOverlayOpen]="isOpen()"
  [cdkConnectedOverlayPositions]="positions"
  [cdkConnectedOverlayFlexibleDimensions]="true"
  [cdkConnectedOverlayPush]="true"
  (overlayOutsideClick)="close()"
  (detach)="close()">
  <div class="ax-panel" role="dialog" animate.enter="ax-panel-in">...</div>
</ng-template>
protected readonly positions = CARD_OVERLAY_POSITIONS;

2. Close on scroll, the Skolenza way

The shell scrolls an inner container, so CDK's close scroll strategy never fires. Use closeOverlayOnScroll() (capture-phase listener that ignores scrolling inside .cdk-overlay-pane), or appCdkCloseMenuOnScroll for a CdkMenuTrigger. 

constructor() {
  closeOverlayOnScroll(() => this.close(), () => this.isOpen());
}

3. Reposition when the panel resizes

A panel that opens as a skeleton and grows keeps the position that suited the skeleton. Put appRepositionOnResize on the same ng-template as cdkConnectedOverlay.

ConcernSetting
BackdropDialog/drawer: hasBackdrop with --ax-overlay-scrim. Menu/popover: transparent backdrop (cdk-overlay-transparent-backdrop) or overlayOutsideClick.
Scroll strategyDialog/drawer: block(). Menu/popover/tooltip: reposition() plus the capture-phase close above.

CDK Portal

  • TemplatePortal is the default - the template keeps its injection context and the host component's signals.
  • ComponentPortal when the content is a component with its own store; pass data through an injection token, not @Input assignment after creation.
  • A portal outlet inside a feature must be destroyed with the host - use DestroyRef.onDestroy(() => portal.detach()).
  • Do not portal a form control out of its ControlContainer; for Optimus template markers, use the wrapper pattern in shared/components/ instead.
private readonly vcr = inject(ViewContainerRef);
protected readonly portal = new TemplatePortal(this.tpl(), this.vcr);

CDK Menu & Listbox

  • cdkMenu / cdkMenuItem / cdkMenuTriggerFor give the full WAI-ARIA menu keyboard model free. Add appCdkCloseMenuOnScroll on the trigger.
  • cdkMenuItemCheckbox and cdkMenuItemRadio for stateful items - they manage aria-checked for you.
  • Submenu: [cdkMenuTriggerFor] on the item plus [cdkMenuPosition] for side placement. Keep submenus one level deep; the staffMember action menu is the cautionary tale (13 entries, needs an explicit max-height: 60vh).
  • cdkListbox for multi-select surfaces that are not menus (filter panels, permission pickers): [cdkListboxMultiple], [cdkListboxCompareWith].
  • Menu items are 34px tall, --ax-radius-md, with 10px inline padding and a 16px leading icon slot that stays reserved even when an item has no icon - otherwise labels misalign.

CDK Layout, Clipboard, Text & Scrolling

  • BreakpointObserver - behaviour-level responsiveness only (see Layout). Convert to a signal with toSignal.
  • Clipboard - copy actions; always follow with a toast or an inline "Copied" state that reverts after ~2s (the colour picker does this).
  • TextFieldModule - cdkTextareaAutosize with cdkAutosizeMinRows/MaxRows instead of a manual resize observer.
  • ScrollingModule - cdk-virtual-scroll-viewport once a list can exceed ~200 rows. Fixed item size must match the real row height (34px for menu-style rows) or scrolling drifts.
  • cdkScrollable - register the app's inner scroll container so CDK reposition strategies see it.

Custom CDK overlay component

The reference skeleton every Skolenza floating component starts from: signal-driven, zoneless-safe, tokenised, and using the repo's scroll and reposition helpers. 

import { CdkConnectedOverlay, CdkOverlayOrigin } from '@angular/cdk/overlay';
import { ChangeDetectionStrategy, Component, computed, input, model, signal } from '@angular/core';

import { CARD_OVERLAY_POSITIONS, closeOverlayOnScroll } from '@shared/utilities/overlay';
import { RepositionOnResize } from '@shared/directives';

@Component({
  selector: 'app-inspector-popover',
  imports: [CdkConnectedOverlay, CdkOverlayOrigin, RepositionOnResize],
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <button
      type="button"
      class="ax-trigger"
      cdkOverlayOrigin
      #trigger="cdkOverlayOrigin"
      [attr.aria-expanded]="isOpen()"
      aria-haspopup="dialog"
      (click)="toggle()">
      {{ label() }}
    </button>

    <ng-template
      cdkConnectedOverlay
      appRepositionOnResize
      [cdkConnectedOverlayOrigin]="trigger"
      [cdkConnectedOverlayOpen]="isOpen()"
      [cdkConnectedOverlayPositions]="positions"
      [cdkConnectedOverlayFlexibleDimensions]="true"
      [cdkConnectedOverlayPush]="true"
      (overlayOutsideClick)="close()"
      (detach)="close()">
      <div
        class="ax-panel"
        role="dialog"
        [attr.aria-label]="label()"
        animate.enter="ax-panel-in"
        animate.leave="ax-panel-out"
        (keydown.escape)="close()">
        <ng-content />
      </div>
    </ng-template>
  `,
  styleUrl: './inspector-popover.css',
})
export class InspectorPopover {
  readonly label = input.required<string>();
  readonly isOpen = model(false);

  protected readonly positions = CARD_OVERLAY_POSITIONS;

  constructor() {
    closeOverlayOnScroll(() => this.close(), () => this.isOpen());
  }

  protected toggle(): void {
    this.isOpen.update((open) => !open);
  }

  protected close(): void {
    this.isOpen.set(false);
  }
}

Focus handling is the part most often skipped. If the panel contains controls, move focus into it on open (cdkTrapFocus cdkTrapFocusAutoCapture) and return it to the trigger on close. If it is read-only, leave focus on the trigger and make Esc close it.

Ship checklist

Run this before opening a PR for any custom CDK component.

  • Optimus genuinely could not do this, and the decision is written in the PR.
  • No hardcoded hex; colours read --p-*, geometry reads --ax-*.
  • Geometry in px; rem only for type (root is 13px).
  • All eight states implemented: rest, hover, focus-visible, active, selected, disabled, loading, error.
  • Focus ring visible at 2px/2px offset; focus returns to the trigger on close.
  • Full keyboard model for the pattern (arrows, Home/End, Esc, type-ahead where applicable).
  • Correct roles and ARIA; icon-only controls have an aria-label.
  • AXE clean; bun run lint passes including template a11y rules.
  • Dark mode checked: shadows dropped, borders present, contrast holds.
  • Motion uses animate.enter/animate.leave or CSS classes, honours prefers-reduced-motion, and animates only opacity/transform.
  • Overlay uses CARD_OVERLAY_POSITIONS, closeOverlayOnScroll, appRepositionOnResize, and a panelClass.
  • Responsive down to 320px; touch targets ≥24px, ≥40px on primary touch flows.
  • Component stylesheet under the 4kB warning budget.
  • Copy uses hyphens or colons, never em dashes; labels are sentence case, verb first.
  • Signals + OnPush; no zone.js assumptions, no fakeAsync in specs.
